Virtualization is the foundational layer of modern computing, rapidly expanding across hyperscale cloud infrastructure, physical AI, automotive systems, and embedded edge devices. As Arm-based platforms scale across these highly divergent workloads, the underlying virtual machine monitors and hypervisors must deliver native performance without the overhead of emulation taxes or fragmented tooling.

Ensuring robust, consistent virtualization support requires bridging the gap between new hardware extensions and upstream software readiness.

The CoreCollective Virtualization Working Group serves as the industry's collaborative forum for hypervisor developers, firmware engineers, and silicon vendors to coordinate architecture-level enablement that no single organization can deliver alone.

## Building a Native Virtualization Ecosystem

Self-sustaining enablement for Arm virtualization requires tight cross-industry alignment to close the gap between silicon capabilities and software support without relying on isolated, downstream vendor forks.

The Working Group brings together competitors and partners to advance the open-source virtualization stack for Arm, ensuring interoperability and unified upstream contributions for hypervisors, standard device interfaces, and userspace monitors:

* Propose, align, and prioritize existing open source collaborative efforts.
* Identify new collaboration opportunities across the software stack.


## Areas of Active Collaboration

### 1. VirtIO

* **What**: Upstreaming virtio-msg, a new message-based transport protocol for VirtIO. This fills the gap for environments where existing trap-and-emulate transports (like PCI or MMIO) are not natural abstractions, such as Asymmetric Multiprocessing (AMP) systems, secure partitions, firmware co-processors, or software-only VM-to-VM endpoints

* **Why it matters**: VirtIO is the de facto standard for paravirtualized devices in Linux. While traditional transports work for standard VMs, they create significant developer friction in heterogeneous systems. The new virtio-msg protocol provides a critical, lightweight abstraction tailored for emerging Physical AI and automotive use cases.

* **Why open collaboration wins**: Defining a standardized message-based transport prevents fragmented, vendor-specific workarounds. Cross-industry alignment streamlines upstream OASIS standard integration and Linux kernel reviews by demonstrating broad ecosystem demand and shared engineering support.

### 2. XEN

* **What**: Implementing missing architectural features in the Xen hypervisor for Arm, targeting Pointer Authentication, GICv5 support, and new atomic operations, alongside hardening real-time capabilities for certification efforts.

* **Why it matters**: Xen is a critical dependency for embedded, automotive, and safety-focused systems requiring a small-footprint, independent hypervisor. Upstreaming new architectural features allows these demanding environments to fully leverage modern Arm CPU performance and security mechanisms without carrying local patches.

* **Why open collaboration wins**: Sharing the engineering burden for complex architectural enablement prevents duplicated effort. Collaborative upstreaming accelerates the availability of safety-critical features, de-risking deployment for robotics and automotive vendors relying on certified hypervisors.

### 3. VMMs & KVM

* **What**: Exercising KVM APIs and implementing logic for new architectural features using QEMU as the foundational Virtual Machine Monitor (VMM). This includes leveraging QEMU's dynamic JIT (TCG) for ISA virtualization and block layer capable of supporting complex copy-on-write storage chains.

* **Why it matters**: QEMU remains the gold standard and initial proving ground for new architecture features, enabling engineers to work out guest software kinks long before hardware is broadly available. This ensures a seamless migration path from emulation to hardware-accelerated KVM virtualization.

* **Why open collaboration wins**: Aligning early on QEMU implementations ensures that newer VMMs (such as Cloud Hypervisor) inherit stable, well-tested KVM APIs. Openly collaborating on the emulation layer unblocks maintainers and accelerates software readiness across the entire Arm ecosystem.
