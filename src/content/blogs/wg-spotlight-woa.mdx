Did ARM64 PCs come up in your recent search for a new laptop? Windows on Arm is
gaining momentum to deliver powerful computing with long battery life.  Even
bigger gains will be unlocked as more applications move from running emulated to
running natively.

The industry collaboration to make this a reality is happening at CoreCollective
in the Windows on Arm working group.  Learn about what we’re working on and how
you can get involved.

Building a complete, self-sustaining ecosystem requires cross-industry
alignment. Porting, optimizing, and maintaining the vast landscape of
open-source dependencies requires many efforts across a diverse set of
stakeholders.

The CoreCollective Windows on Arm (WoA) Working Group was formed to unite
hardware vendors, OS teams, open source maintainers, software distributors, and
application creators around shared enablement goals, to pave the way to a rich,
fully native Windows on Arm platform.

## Vision & Membership

The vision of the WoA Working Group is to support a growing, self-sustaining Arm
open source ecosystem for Windows. The purpose of the group is to: Propose,
align, and prioritize existing open source collaborative efforts.  Identify new
collaboration opportunities across the Windows on Arm software stack.  Current
member companies actively driving this initiative are **Arm, CIX, Linaro,
Microsoft, NVidia,** and **Qualcomm**.


## Areas of Active Collaboration

### 1. Python Package Support

* **What:** Working towards Windows ARM64 wheels for the top 1000 (and more)
most-downloaded Python packages on PyPi.  We are over 95% of the way there!

* **Why it matters:** Python underpins modern data science, scripting, and machine
learning workflows. Wheel availability eliminates friction for developers, so
that they don’t have to build the package from source.

* **Why open collaboration wins:** Coordinating across CoreCollective WoA working
group member companies has enabled division of labour, prevented duplication of
efforts, and streamlined upstreaming through peer review and PR support, while
leveraging combined networks to unblock contributions with key maintainers.

### 2. Toolchains & Compilers (LLVM & GCC)

* **What:** Upstream enhancement of LLVM and GCC for Windows on Arm targets.
Initiatives include MSVC intrinsics in Clang and ARM64 EC support.

* **Why it matters:** Robust toolchains enable upstream projects to leverage
native ARM64 optimizations directly without fragmentation.

* **Why open collaboration wins:** Coordinating compiler developments across
hardware vendors, OS teams, and maintainers prevents isolated workarounds,
accelerates upstream patch reviews, and ensures all downstream projects benefit
automatically from shared performance gains and toolchain fixes.

### 3. Developer Tooling & Ecosystem Visibility

* **What:** Building and cross-promoting the Windows on Arm Software Ecosystem
Dashboard, Arm AppReady developer guides, and development/porting tools like a
VS Code extension with GitHub Copilot chat integration.

* **Why it matters:** Engineers need clear visibility into package/app readiness
and practical tooling to assist in migrating x64 codebases to Arm64.

* **Why open collaboration wins:** Open collaboration helps spread information
about resources more widely & to bring to light gaps / pain points that need to
be addressed.
